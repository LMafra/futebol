# ADR 0001 — Arquitetura modular, ciclo de pontuação e contratos

- Status: aceito · Data: 2026-10-31
- Fonte: prompt do orquestrador (3 docs de arquitetura + 7 correções não encontrados em disco → contratos derivados do prompt)

## Contexto
Bolão (palpites de placar), Cartola (fantasy) e Simulador compartilham partidas, times e usuários. Pontuação precisa ser idempotente, reversível e auditável.

## Decisão 1 — Tree (monolito modular, packwerk)
```
app/{admin,components,jobs,services,policies,models,controllers}
engines/core/       Team, Match, Championship, User, AuditLog, CsvImport
engines/bolao/      Pool, Prediction, PredictionScore
engines/cartola/    Squad, Lineup, PlayerScore
engines/simulador/  Simulation (read-only sobre core)
```
- Dependência: bolao/cartola/simulador → core. Nunca core → engine. Nunca engine ↔ engine.

## Decisão 2 — State machine `Match` (AASM)
| evento | de → para | guard | efeito |
|---|---|---|---|
| start_match! | scheduled → live | match_date <= now | — |
| finish_match! | live → finished | placar presente | enqueue ProcessMatchPointsJob |
| mark_scored! | finished → scored | scores_calculated_at.nil? | grava scores_calculated_at + scoring_token |
| revert_match! | scored → finished | scores_calculated_at.present? | ver ordem abaixo |

**Guard corrigido — ordem obrigatória em `revert_match!`:**
1. guard lê `scores_calculated_at.present?` (ainda não zerado)
2. `RevertMatchPointsService` executa (discard dos scores + AuditLog) **ANTES** de zerar
3. só então `scores_calculated_at = nil`, `scoring_token = nil`, `reversal_token = SecureRandom.uuid`
- Zerar antes do revert = guard falso + pontos órfãos (bug corrigido).

## Decisão 3 — Colunas críticas (`matches` + tabelas de score)
| coluna | tipo | regra |
|---|---|---|
| status | string, not null | check constraint IN (scheduled, live, finished, scored) |
| scores_calculated_at | datetime, null | presente ⇔ status = scored (check constraint) |
| scoring_token | uuid, null | idempotência do ProcessMatchPointsJob; unique parcial |
| reversal_token | uuid, null | idempotência do revert |
| discarded_at | datetime, null | soft delete (discard) em scores/predictions |

## Decisão 4 — Jobs e serviço de broadcast
| módulo | interface | idempotência |
|---|---|---|
| ProcessMatchPointsJob | `perform(match_id, scoring_token)` | no-op se `match.scoring_token == token`; rescue → log + Sentry, re-raise |
| RevertMatchPointsJob | `perform(match_id, reversal_token)` | no-op se token já aplicado |
| ProcessCsvImportJob | `perform(csv_import_id)` | upsert por `external_id`; streaming `csv_file.open`; rescue → `status: "failed"` |
| BroadcastUpdateService | `call(match)` | lock `Rails.cache.write(key, unless_exist: true)` contra broadcast duplicado |

## Decisão 5 — Autorização
- Pundit por action de admin (`index? show? create? update? destroy?` + `revert?`, `import?`)
- 5 policies: MatchPolicy, CsvImportPolicy, PoolPolicy, SquadPolicy, AuditLogPolicy
- ActiveAdmin usa `Pundit adapter`; `verify_authorized` em toda custom page

## Decisão 6 — Nomes
- `scoring_token` (uuid) **e não** `scoring_version` (int): token identifica a execução, não ordena; evita race em incremento
- `match_date` **e não** `kickoff_at`: termo do domínio/CSV de origem

## 7 correções incorporadas
1. Ordem do guard em `revert_match!` (Decisão 2)
2. `scoring_token` uuid em vez de `scoring_version`
3. `match_date` em vez de `kickoff_at`
4. Migrations usam `add_check_constraint` (não `add_constraint`)
5. CSV via `csv_file.open` em streaming (não `CSV.read`) + rescue → failed
6. `CalculatePreviewService` recebe `candidate_home/candidate_away`
7. Broadcast com `unless_exist`; seeds sem array em `belongs_to`; AuditLog com `ip_address`

## Consequências
- + Pontuação reexecutável e reversível sem duplicar pontos
- + Engines isoladas (packwerk impede import cruzado)
- − Mais colunas de controle; constraints exigem migrations cuidadosas
